# 建議規則：審自己的分支

建議只有三種：修、不修、你判斷。等級不列入判斷，P3 可以建議修，P1 也可以建議不修。

## 修

符合任一條：

- 查證成立、這次造成，而且會寫錯資料、卡住流程或回傳錯誤結果。
- 查證成立、這次造成，而且修法只有一兩行、不影響其他行為。

## 不修

標出下列一個理由，並附上證據（`file:line`、ticket 條目或查過的指令）。P0、P1 只能用前兩個理由。

| 理由 | 成立條件 |
| --- | --- |
| 需求已定案 | ticket、規格或 issue 明訂這樣做，或明訂這次不做 |
| 條件不成立 | 順著程式碼或環境查過，觸發條件走不到 |
| 不是這次造成 | diff 沒有動到這段，影響也不是資料錯誤 |
| 非專案規範 | 依據只有使用者的個人設定（例如 `~/.claude/CLAUDE.md`），repo 的規範沒有這條 |
| 抽共用不划算 | 重複量小，或各處會各自演變，抽出來不會比較好讀 |

建議欄寫成 `不修：條件不成立`。修法欄照常填，使用者才看得出哪些條目順手就能改。

## 你判斷

其餘都歸這裡，常見的有：

- 發生機率取決於業務情境或資料量。
- 修法大，或會影響其他流程。
- 實作和規格有出入，不確定該改哪一邊。
- 既有問題，但會造成資料錯誤。
- 五件事有任何一件查不到。

判不準時一律歸這裡。
