# Standards 軸：工程基準

回答一個問題：**本次 diff 的寫法，是否達到這個 repository 與合併前應有的工程基準？**需求做得對不對屬於 Spec 軸；資安、權限、信任邊界、交易與併發屬於 Risk 軸，本軸都不判斷。

逐節核對本次 diff，**只套用 diff 實際涵蓋的節**；每一節都要在涵蓋清單交代結論。各表的嚴重度是建議值，最終由主流程判定。第 1 至 4 節與技術無關，第 5 節為技術別補充，只在專案使用該技術時適用。

---

## 0. 依據與優先序

1. **repo 記載的規範**（主流程提供的檔案清單）：違反時引用檔案與條文。
2. **本文件第 1 至 5 節**：repo 沒有記載時的基準。

寫法慣例（命名、結構、分層、錯誤處理風格、共用方式）兩者衝突時以 repo 規範為準；repo 明確認可的寫法，不以本文件提出候選。已由 formatter、analyzer、linter 或 CI 強制的項目略過。

## 1. 正確性與回歸

| 檢查 | 嚴重度 |
| --- | --- |
| Off-by-one、邊界條件錯誤 | P1 |
| 可由 diff 直接判斷的邏輯錯誤 | P1 |
| 狀態轉換缺漏或允許非法轉換 | P1 |
| 修改共用方法、契約或既有流程，使其他呼叫端行為改變 | P1 |
| 取值前缺少 null 或空集合檢查 | P2 |
| 非同步路徑的未處理例外 | P2 |
| 回傳與實際結果不符的 HTTP status code | P2 |

改到共用方法、基底類別、共用元件或既有流程時，找出所有呼叫端，確認每個呼叫端在新行為下仍然成立。

## 2. 實質效能

| 檢查 | 嚴重度 |
| --- | --- |
| N+1 查詢（迴圈中逐筆呼叫資料庫） | P2 |
| 迴圈內的網路 I/O 或外部呼叫 | P2 |
| 同一資料在同一流程內明顯重複查詢 | P2 |
| 無界限載入大量資料（缺少分頁、篩選或筆數上限） | P2 |
| 可批次卻逐筆執行大量寫入 | P2 |
| 新欄位用於 `WHERE` 或 `JOIN` 但缺少索引 | P2 |
| 阻塞重要流程的同步 I/O | P2 |
| 演算法複雜度在合理資料量下快速惡化 | P2 |

候選要附**資料量或呼叫頻率的依據**：迴圈來源是什麼集合、預期有多少筆、這條路徑多常被呼叫。

## 3. API 向後相容性

重點是保護**外部 consumer**（前端、第三方、App）不受 server-side 變更影響。

破壞性變更一律 **P0**：

| 異動類型 | 範例 |
| --- | --- |
| 回應模型移除對外欄位 | `paymentType` 被刪除 |
| 回應模型欄位改名 | `paymentType` → `paymentCategory` |
| 回應模型欄位型別改變 | 數值 → 字串 |
| Route 移除或路徑改變 | `v1/orders` 變更 |
| HTTP method 改變 | `GET` → `POST` |
| 新增必填請求參數且無預設值 | 新增 `required` 欄位 |
| enum 值移除 | `Cash` 被刪除 |

可向後相容但仍需提醒：

| 異動類型 | 嚴重度 | 說明 |
| --- | --- | --- |
| enum 新增值 | P2 | consumer 的分支處理需確認有 default |
| 回應模型新增選填欄位 | P3 | consumer 不需改動，但提醒前端更新 |
| 新增 endpoint、請求新增有預設值的選填欄位 | P3 | 無影響 |

判斷破壞性變更時，優先檢視對外契約檔案的移除行（`-` 開頭）。

## 4. 程式碼品質

| 檢查 | 嚴重度 |
| --- | --- |
| 重複的業務規則或分支判斷，已造成或高機率造成行為分歧、修正遺漏或安全問題 | P2 |
| 死碼（不可達分支、未使用變數） | P2 |
| 命名不符合既有程式碼或 `CONTEXT.md` 的既有慣例 | P2 |
| 單純重複的邏輯，抽出共用可降低維護成本 | P3 |
| 單一方法過長且無明確理由 | P3 |
| 魔法數字或字串應改為常數或列舉 | P3 |

- **重複**：同一個判斷條件或 `switch` 在本次 diff 的多處出現時，比對各處是否已經不一致；已不一致或規則明顯會一起變動，列 P2，否則列 P3。
- **命名**：比較對象是同模組、同職責的既有名稱與 `CONTEXT.md` 術語；只是「可以更達意」的命名不構成候選。

## 5. 技術別補充

### .NET / C#

只在專案為 .NET / C# 時適用。

| 檢查 | 嚴重度 |
| --- | --- |
| async 方法使用 `.Result` 或 `.Wait()` 阻塞（deadlock 風險） | P1 |
| `Task` 未 `await` | P1 |
| `IDisposable` 型別未以 `using` 釋放 | P2 |
| `catch (Exception)` 過於廣泛且未重拋或記錄 | P2 |
| Library 層級缺少 `ConfigureAwait(false)` | P3 |

對應上面各節的具體形式：

| 通用規則 | .NET / EF Core 的具體形式 |
| --- | --- |
| N+1（第 2 節） | 迴圈內存取未 `Include` 的導覽屬性（lazy loading），或迴圈內呼叫 `Find`、`FirstOrDefault`、`ToList` |
| 無界限載入（第 2 節） | 在 `ToList()` 之後才做 `Where`、`Skip`、`Take` |
| Route 與必填參數（第 3 節） | `[Route]` 變更、新增 `[Required]` 參數 |

檢視破壞性變更的起點：

```bash
git diff <target>...HEAD -- '**/*Dto.cs' '**/*Response.cs' '**/*Controller.cs' | grep '^-.*public'
```
